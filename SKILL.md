# Viral Posts Engine

## Активация

Пользователь вызвал `/viral-posts` — выполняй **Протокол работы** ниже.
Сообщи кратко: «Viral Posts активирован» и определи режим (анонс / саммари / обычный пост).

**Reference-файлы** (читать по необходимости):
- [`reference/announcements.md`](reference/announcements.md) — анонс эфира
- [`reference/summaries.md`](reference/summaries.md) — саммари после эфира
- [`reference/hooks-bank.md`](reference/hooks-bank.md) — расширенный банк хуков

Парный скилл для видео: **viral-reels-engine** (`/viral-reels`) — та же методология под Reels/Shorts/TikTok.
Ставь рядом; для текста работай этим скиллом, для роликов — тем.

Навык превращает любую тему, эфир или транскрипт в **текстовый пост для Telegram-канала**,
заточенный под максимальное внимание и целевое действие. Построен на адаптации методологии
viral-reels-engine (разбор 945 реальных вирусных Reels) под текст: в тексте нет видеоряда,
поэтому всю работу делают **первая строка, ритм абзацев и конкретика**.

Типичные задачи: **АНОНС** (до эфира → регистрации/приходы) и **САММАРИ** (после эфира → охват + сохранения),
плюс обычный вирусный пост без привязки к эфиру.

---

## НИША (обязательный параметр)

Ниша **не зашита**. Не подставляй по умолчанию отношения / психологию / здоровье / эзотерику /
брак / семью / психосоматику — это только примеры в reference, не целевая аудитория.

1. Если пользователь **назвал нишу** (или она ясна из запроса) — зафиксируй и пиши только под неё.
2. Если ниши нет — задай **один** вопрос: «В какой нише пишем и кто аудитория?» Не начинай пост без ответа
   (кроме случая, когда пользователь явно сказал «любая / не важно» — тогда возьми нишу из фактуры темы).
3. Все хуки, примеры боли, CTA и тон **адаптируй под названную нишу**. Чужие нишевые примеры из
   reference переписывай, не копируй дословно.

---

## ДВА ПОДНАВЫКА (маршрутизация)

Сначала определи, что именно нужно, и подгрузи нужный reference-файл:

- **Анонс эфира** (зовём людей, цель — регистрации/приходы) → читай `reference/announcements.md`
- **Саммари после эфира** (пересказ для тех, кто не был, цель — охват + сохранения) → читай `reference/summaries.md`
- **Обычный вирусный пост** (мысль/польза/история без привязки к эфиру) → работай по этому файлу
- Банк хуков под текст (расширенный) → `reference/hooks-bank.md`

Если запрос смешанный или неясный — задай **одну** уточняющую и предложи рабочий вариант.

---

## ТРИ ЗАКОНА ТЕКСТОВОГО ПОСТА

1. **Первая строка решает всё.** В ленте Telegram виден только первый абзац (до «развернуть»).
   Если первая строка не цепляет за 1 секунду — пост мёртв. Никаких «Друзья, привет!», «Сегодня
   хочу поделиться», «Как у вас дела». Хук — сразу, первым словом.
2. **Читатель должен либо дочитать, либо отреагировать.** Вирусность текста = дочитывания +
   сохранения + пересылки + комментарии. Каждый пост проектируется под одно из этих действий.
3. **Сначала смысл (фактура), потом упаковка.** Сначала вытащи голую мысль, историю или пользу,
   потом надень хук и структуру. Так сохраняется живой человеческий тон, который и цепляет.

---

## ПРОТОКОЛ РАБОТЫ

1. **Диагностика (минимум вопросов).** Нужно: **ниша + аудитория** (см. блок выше), что за пост
   (анонс / саммари / обычный), тема/фактура (или транскрипт/саммари эфира), цель
   (регистрации / охват / сохранения / комментарии / прогрев).
   Без ниши — сначала один вопрос про нишу. Если фактуры мало — ещё **одна** уточняющая, не три.
2. **Выбор типа поста** из 8 ниже (для анонса/саммари — бери каркас из reference-файла).
3. **Конструирование хука** — 3 варианта первой строки из банка хуков. Хук создаёт разрыв
   любопытства, провокацию, узнавание или обещание конкретной пользы.
4. **Сборка тела** по структуре выбранного типа.
5. **Концовка + CTA** под цель.
6. **Прогон по чеклисту** и **проверка форматирования под Telegram**.
7. **Выдача** в чистом виде, готовом к копированию (см. «Формат и выдача»).

---

## 8 ТИПОВ ВИРУСНОГО ТЕКСТОВОГО ПОСТА

### 1. Личная история / исповедь
**Когда:** доверие + эмоциональный охват, экспертность через свой путь.
**Хук:** шокирующее личное признание. «Я трижды уходил из семьи», «Когда узнал, что болезнь — выдумка».
**Структура:** признание → завязка → дно/поворот → инсайт → обобщение для читателя.
**Концовка:** мысль-вывод как подарок; иногда мягкий вопрос.

### 2. Жёсткая правда / мысль-пощёчина
**Когда:** характерная экспертка, цель — спор в комментариях и сохранения.
**Хук:** «Вы не готовы это услышать, но…», «Жёсткая правда про [тему]».
**Структура:** предупреждение «будет неприятно» → 3-4 конфронтационных тезиса, каждый с новой строки.
**Концовка:** «С чем согласны, а с чем нет? Пишите».

### 3. Чек-лист / «сохрани, чтобы не потерять»
**Когда:** польза, цель — сохранения и подписки.
**Хук:** «[Число] признаков/правил/ошибок…», «10 лет терапии в одном посте».
**Структура:** заголовок-обещание → плотный перечень, каждый пункт с новой строки, без воды.
**Концовка:** «Сохрани», «Что добавишь?».

### 4. Метафора / глубокий инсайт
**Когда:** философский/эмоциональный охват, пересылки «в точку».
**Хук:** ёмкая метафора или контринтуитивный вопрос. «Развод не заканчивается разводом».
**Структура:** образ → раскрытие через 2-3 коротких абзаца → смысл «доезжает» в конце.
**Концовка:** оставить мысль звучать; вопрос.

### 5. Разбор через «теорию»/фреймворк
**Когда:** экспертный авторитет + любопытство (психология/отношения).
**Хук:** «[Теория/закон] объясняет, почему [узнаваемая боль]».
**Структура:** обещание раскрыть → вводишь принцип → применяешь к узнаваемому примеру → вывод.
**Концовка:** обобщающий принцип; мягкий CTA.

### 6. Контринтуитивный разворот
**Когда:** ломаем шаблон аудитории, цель — дочитывание и репост.
**Хук:** «Почему [очевидно правильное] на самом деле вредит».
**Структура:** называешь общепринятое → разворачиваешь «но» → объясняешь механику → новый угол.
**Концовка:** «Знай это» / вопрос.

### 7. Секрет / «никто не говорит»
**Когда:** инсайт, который «все скрывают», цель — сохранения и пересылки.
**Хук:** «Не знаю, почему все молчат, но…», «Никто не скажет тебе, что…».
**Структура:** интрига-секрет → раскрытие сути → почему об этом молчат → что с этим делать.
**Концовка:** «Сохрани, чтобы не забыть».

### 8. Анонс / Саммари эфира
→ Это два отдельных режима со своими каркасами. См. `reference/announcements.md` и
`reference/summaries.md`. Не пиши их «на глаз» — там выстраданная структура под регистрации и охват.

## БАНК ХУКОВ (краткий; расширенный — в reference/hooks-bank.md)

Всегда генерируй **3 варианта** первой строки.

1. **Личное признание:** «Я [шокирующий факт]» / «Когда я узнал, что…».
2. **Число + обещание:** «[3/5/7] [правд/признаков/ошибок] про [тему]».
3. **Контринтуитивный вопрос:** «Почему [очевидное] — на самом деле ловушка?»
4. **Жёсткая правда:** «Вы не готовы это услышать, но…».
5. **Секрет:** «Никто не говорит, что [инсайт]».
6. **Метафора-ярлык:** «[Явление] — это [неожиданный образ]».
7. **Дейксис + интрига:** «Вот на этом примере видно всё про [тему]».
8. **«Знаете, почему…»:** «Знаете, почему [болезненный вопрос аудитории]?»

**Правила хука:** ≤ 8-10 слов; никаких приветствий и разогрева; конкретика вместо абстракции;
одна эмоция (шок/любопытство/узнавание/польза); хук — это ПЕРВАЯ СТРОКА, видимая в ленте.

---

## МЕХАНИКА УДЕРЖАНИЯ В ТЕКСТЕ

- **Первая строка = хук**, она же видна в превью ленты до «развернуть».
- **Короткие абзацы по 2-3 строки**, пустая строка между ними. Стена текста убивает дочитывание.
- **Один абзац = одна мысль.** Длинное предложение разбивай.
- **Открытая петля:** «дальше расскажу, что было самым неожиданным» — держит до конца.
- **Конкретика и цифры** (3 кризиса, 109 минут, перелом носа) — достоверность и «цепляемость».
- **Ритм:** чередуй короткие рубленые фразы и средние. Монотонность усыпляет.
- **Эмодзи — акценты, а не украшение.** 3-5 на пост, по смыслу, не в каждой строке.
- **Сильная последняя строка** — вопрос, вывод или призыв. Не «вот как-то так».

---

## ФОРМАТИРОВАНИЕ ПОД TELEGRAM (важно для чистого вида)

- Разделяй абзацы **двойным переносом строки** (пустая строка между блоками) — иначе текст слипается.
- Списки — каждый пункт **с новой строки**, можно с эмодзи-маркером (• или ▪️ или 1️⃣) в начале.
- Не используй markdown-таблицы и «#» заголовки — Telegram их не рендерит, выглядит мусором.
- Жирный/курсив — только если пост публикуется с parse_mode (иначе звёздочки видны как текст).
  По умолчанию для копипаста делай **plain text** без `*` и `_`.
- Не ставь ссылки в первую строку (превью ленты их обрежет некрасиво).
- Длина: пост 120-250 слов; анонс короче (80-150); чек-лист может быть длиннее, если плотный.

---

## ЧЕКЛИСТ ВИРУСНОСТИ (прогон перед выдачей)

1. Первая строка цепляет за 1 секунду и работает как превью в ленте?
2. Понятно, ЗАЧЕМ дочитывать (петля/обещание/интрига)?
3. Выбран тип поста и соблюдена его структура?
4. Есть конкретика (цифры, детали, имена, образы), а не общие слова?
5. Абзацы короткие, есть пустые строки, нет стены текста?
6. Концовка спроектирована под целевое действие?
7. CTA (если есть) — уместный и не в начале?
8. Тон живой, человеческий, не «гладко-рекламный»?
9. Форматирование чистое под Telegram (переносы, без сломанного markdown)?

Если хотя бы один пункт не выполнен — дорабатывай, не выдавай.

---

## ФОРМАТ И ВЫДАЧА

Выдавай **готовый к копированию текст поста** — без служебных пометок внутри самого поста.
Если пользователь не просил несколько вариантов — дай один сильный пост.

Структуру можно показать так:

```
ХУК (3 варианта первой строки):
1) …
2) …
3) …

ГОТОВЫЙ ПОСТ (с выбранным хуком №1):
[чистый текст, готовый к копипасту, с переносами строк]
```

Если просят несколько идей постов — дай списком: тип + хук + одно предложение сути, потом
предложи развернуть любой в полный пост.

## РЕЖИМЫ

- **Анонс эфира:** → `reference/announcements.md`
- **Саммари эфира:** → `reference/summaries.md`
- **Пост с нуля:** тема → тип → хук → структура → выдача.
- **Идеи/контент-план:** 5-10 постов под нишу, хук + суть каждого.
- **Докрутка поста:** определи тип, прогони по чеклисту, усиль хук и концовку, почини форматирование.
